# 0004: Text

Game text is Shift-JIS in `main.dat` and in `AdvSys.bnd` (FMG, see [0001](0001-initial-findings.md)). `scripts/text_survey.py` counts it from the output of `scripts/maindat.py`.

## Size

Unique strings that contain kana or kanji:

| | Additional I | Additional II |
|---|---|---|
| Global table | 777 | 808 |
| Pointer strings | 1,225 | 1,784 |
| Record names | 461 | 458 |
| All unique | 2,176 | 2,775 |
| Characters | 49,582 | 63,387 |

Chunks repeat item, spell and menu records. Additional I has 47,895 record names and 7,245 pointer strings before deduplication.

## Global table

In the `main.dat` header body. Offsets are file offsets.

| Offset | Field |
|---|---|
| `0x204` | Count (2000) |
| `0x208` | Pointer to the offset table (`0x214`) |

Each table entry is a u32 file offset of a NUL-terminated string. Unused entries hold `テスト`. Examples:

| Index | Text |
|---|---|
| 1 | `特に変わったところはない` |
| 3 | `鍵がかかっている\r\nあけるには鍵が必要だ` |
| 4 | `はい` |
| 5 | `いいえ` |

## Chunks

A chunk is a room, a town or a minigame. Chunk 0 is `街・戦闘`, chunk 1 is `オープニング`, chunks 2–7 are casino games, and later chunks are dungeon rooms such as `B12F　神殿　水部屋`.

### Header

| Offset | Field |
|---|---|
| `0x00` | Size |
| `0x04` | Chunk index |
| `0x10`, `0x14`, `0x18` | Pointers to regions A, B and C |
| `0x20` | Name, 0x20 bytes |
| `0x44` | File offset of the chunk's sound BND |
| `0x48` | Pointer to the object count |
| `0x54` | Pointer to the object pointer list |

All pointers inside a chunk are absolute `main.dat` file offsets. Regions A and B are pointer lists. Region C is a table of 16-byte entries that index images. Objects hold command records; the command format is not known.

### Pointer strings

NUL-terminated Shift-JIS. A u32 file offset somewhere in the same chunk points to the first byte. Dialogue uses this form:

```text
「行くのは勝手だが、\r\n　死ぬなら深い層にしてくれ。\r\n　我々も死体を回収しなくて済む」
```

### Record names

A record is 0x20 bytes, 16-byte aligned:

| Offset | Size | Field |
|---|---|---|
| `0x00` | 0x18 | Name, zero-padded |
| `0x18` | 2 | Not known |
| `0x1A` | 2 | Index in the list |
| `0x1C` | 4 | `0xFFFF` or a link value (`0x0BBB` seen) |

Menus, items and spells use this form: `話す`, `アイテム`, `魔法`, `回復の水（青）`, `ファイアーボール`. A name holds at most 24 bytes.

## Markup

| Token | Meaning |
|---|---|
| `\r\n` | Line break |
| `　` (U+3000) after a break | Indent inside quoted speech |
| `#e[n]` | Not known. Example: `傷薬を手に入れた。#e[1411400000]` |

## Repacking

- A longer string moves the data after it. Every pointer to moved data needs an update.
- Pointers are absolute file offsets. A chunk that moves in `main.dat` needs all its internal pointers rebased.
- The survey finds pointers by scanning aligned u32 values. A data word can equal a string offset by chance. The command format is needed to locate pointers exactly.
- Record names have a fixed 24-byte field. Longer English names need the field read through a pointer or an abbreviation.
